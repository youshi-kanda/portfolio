# AIコンサルCRM 代理店・コンサル利用仕様書 v0.1

## 1. 本書の目的

本書は、AIコンサルCRMを代理店・コンサル・LINE運用代行者・Lステップ構築者・SNS運用支援者が利用する場合の仕様を定義するものである。

本サービスは、個人店・小規模店舗が公式LINEを主要な顧客接点として活用しながら、顧客状態・売上課題・地域ニーズを整理し、集客・再来店・顧客フォロー・発信施策をAIに相談しながら実行できるAIコンサル型CRMである。

代理店・コンサル利用では、店舗単体利用とは異なり、以下を明確にする必要がある。

- 代理店・コンサルがどの範囲まで店舗データを閲覧・編集できるか
- 複数店舗をどう管理するか
- 店舗診断、提案書、月次レポートをどう作成するか
- 公式LINEのみで足りる店舗と、Lステップ等が必要な店舗をどう判断するか
- 顧客個人情報をどこまで扱うか
- 代理店作成文案・施策・レポートの承認責任をどう管理するか
- 代理店が自社ノウハウをテンプレート化できるか
- 将来的に代理店向けプラン・権限・請求をどう分けるか

---

## 2. 基本方針

### 2.1 代理店・コンサル利用の位置づけ

本サービスは、店舗が直接利用するだけでなく、代理店・コンサルが複数店舗の支援を効率化するための業務支援ツールとしても利用できる。

代理店・コンサル利用における本サービスの役割は、以下である。

```text
店舗データ・発信状況・売上課題を整理
↓
AIが診断・改善提案・施策案を生成
↓
代理店・コンサルが確認・編集
↓
店舗へ提案・承認依頼
↓
LINE/SNS/Google/個別対応で実行
↓
結果を記録
↓
月次レポート・改善提案へ反映
```

### 2.2 本サービスが支援する代理店業務

| 業務 | 支援内容 |
|---|---|
| 店舗診断 | 売上、顧客、発信、LINE運用状況を整理する |
| 改善提案 | 今週・今月やるべき施策を提案する |
| LINE運用支援 | 配信対象、配信目的、文案、タグ案を整理する |
| Lステップ設計支援 | タグ設計、シナリオ案、改善案を作る |
| SNS/Google発信支援 | 投稿テーマ、文案、投稿カレンダーを作る |
| 月次報告 | 施策結果、課題、次月計画をレポート化する |
| 複数店舗管理 | 担当店舗の状況を一覧で確認する |
| 営業提案 | 新規店舗向けの診断・提案書を作る |

### 2.3 基本思想

代理店・コンサル利用では、以下を基本思想とする。

| 方針 | 内容 |
|---|---|
| 店舗データは店舗に帰属 | 代理店は支援権限を持つが、店舗データを所有しない |
| 最小権限 | 支援に必要な範囲だけ閲覧・編集できる |
| 個人情報は原則制限 | 初期は集計・診断中心とし、個人情報閲覧は店舗許可制にする |
| AI提案は支援材料 | 代理店が確認・編集したうえで店舗へ提示する |
| 店舗承認を重視 | 顧客向け配信、外部投稿、重要施策は店舗承認を前提にする |
| 再現性ある支援 | 診断、提案、レポートをテンプレート化する |
| 代理店ノウハウを活かす | 将来的に独自テンプレート・独自提案パターンを持てるようにする |

## 3. 想定利用者

### 3.1 代理店・支援者の種類

| 種別 | 主な利用目的 |
|---|---|
| LINE運用代行者 | 公式LINE配信内容、配信対象、運用改善の支援 |
| Lステップ構築者 | タグ設計、シナリオ設計、改善提案の効率化 |
| L Message構築者 | LINEシナリオ・セグメント運用の設計支援 |
| SNS運用代行者 | Instagram投稿テーマ、投稿文、レポート作成 |
| Googleビジネス支援者 | Google投稿、口コミ返信、地域検索改善支援 |
| 店舗コンサル | 売上改善、リピート改善、客単価改善の提案 |
| 美容・整体・ジム専門支援会社 | 業種特化の改善提案、複数店舗運用 |
| 小規模事業者向け代理店 | 複数業種へのライトなマーケティング支援 |

### 3.2 利用者ロール

| ロール | 主な権限 |
|---|---|
| agency_admin | 代理店管理者。契約、担当者、店舗割当を管理する |

| store_owner | 店舗側承認者。提案・文案・レポートを確認する |
| system_admin | システム運営者。テナント・ログ・障害対応を管理する |

## 4. 契約・テナント構造

### 4.1 基本構造

代理店利用では、以下の構造を採用する。

```text
代理店テナント
  ├─ 代理店ユーザー
  ├─ 担当店舗A
  ├─ 担当店舗B
  └─ 担当店舗C
```

店舗データは店舗単位で分離し、代理店は `agency_store_assignments` により許可された店舗へアクセスする。

### 4.2 データ所有の考え方

| データ | 所有・管理の考え方 |
|---|---|
| 店舗基本情報 | 店舗または契約主体に帰属 |
| 顧客情報 | 店舗に帰属 |
| 売上・予約情報 | 店舗に帰属 |
| 代理店作成の提案書 | 代理店が作成するが、店舗データを含む場合は店舗権限に従う |
| 代理店独自テンプレート | 代理店に帰属 |
| 匿名集計データ | 利用規約・同意に基づきサービス改善に活用可能 |

### 4.3 契約パターン

| パターン | 内容 |
|---|---|
| 店舗契約 + 代理店招待 | 店舗が契約し、代理店を外部支援者として招待する |
| 代理店契約 + 店舗管理 | 代理店が契約し、複数店舗を管理する |
| 共同利用 | 店舗と代理店の両方が利用し、承認・実行を分担する |
| 診断のみ利用 | 代理店が営業提案前の簡易診断に利用する |

### 4.4 初期推奨

初期は、以下を推奨する。

| 項目 | 方針 |
|---|---|
| 契約単位 | 店舗契約または代理店契約の両方に対応できるDB設計にする |
| 実装優先 | 代理店契約 + 複数店舗管理はMVP後半でもよい |
| データ権限 | 店舗単位の閲覧・編集権限を必須にする |
| 請求 | 初期は手動契約・手動請求でもよい |

## 5. 権限設計

### 5.1 権限レベル

| 権限レベル | 内容 | 個人情報閲覧 | 主な用途 |
|---|---|---|---|
| view_report | 集計レポート閲覧のみ | 原則不可 | 月次報告、経営診断 |
| edit_campaign | 施策・文案作成、対象人数確認 | 原則不可、一部マスキング | LINE/SNS運用支援 |
| full_support | 顧客詳細、施策、レポートまで支援 | 店舗許可がある場合のみ可 | 伴走型コンサル |
| admin | 店舗設定、権限、データ取込まで管理 | 店舗許可がある場合のみ可 | 運用代行全般 |

### 5.2 操作権限マトリクス

| 操作 | view_report | edit_campaign | full_support | admin |
|---|---:|---:|---:|---:|
| ダッシュボード閲覧 | ○ | ○ | ○ | ○ |
| 月次レポート閲覧 | ○ | ○ | ○ | ○ |
| 顧客一覧閲覧 | △ 集計のみ | △ マスキング | ○ | ○ |
| 顧客詳細閲覧 | × | ×/△ | ○ | ○ |
| 顧客メモ閲覧 | × | × | △ | ○ |
| 施策作成 | × | ○ | ○ | ○ |
| 文案生成 | × | ○ | ○ | ○ |
| 対象者リスト出力 | × | △ | ○ | ○ |
| CSV出力 | × | ×/△ | △ | ○ |
| データ取込 | × | × | △ | ○ |
| 店舗設定変更 | × | × | × | ○ |
| 承認依頼 | × | ○ | ○ | ○ |
| 最終承認 | × | × | △ 店舗許可時 | ○ 店舗許可時 |

### 5.3 個人情報マスキング

代理店ユーザーには、権限に応じて以下をマスキングする。

| 情報 | マスキング例 |
|---|---|
| 氏名 | 山田花子 → 顧客A / 山田○○ |
| 電話番号 | 090-1234-5678 → 090-****-5678 |
| メール | sample@example.com → s***@example.com |
| LINE表示名 | 一部非表示 |
| 接客メモ | センシティブ項目を非表示または要約表示 |
| 顧客ID | 店舗内IDまたは匿名IDで表示 |

### 5.4 重要操作の制御

以下は、権限だけでなく監査ログを必須にする。

- 顧客データ閲覧
- 顧客データCSV出力
- 対象者リスト出力
- AIによる顧客分析実行
- LINE配信用文案の生成
- 文案のコピー/出力
- 施策の承認依頼
- 店舗承認
- レポートPDF出力

## 6. 代理店向け主要業務フロー

## 6.1 新規店舗診断フロー

### 6.1.1 目的

新規営業または初回支援時に、店舗の現状を把握し、改善余地と支援方針を提示する。

### 6.1.2 フロー

```text
店舗情報を登録
↓
利用中ツールを登録
↓
簡易ヒアリングを入力
↓
可能であれば顧客/売上/予約CSVを取込
↓
AI初期診断を実行
↓
課題・改善優先度を確認
↓
公式LINEのみで足りるか、Lステップ等が必要か診断
↓
提案書を生成
↓
代理店が編集
↓
店舗へ提示
```

### 6.1.3 出力内容

- 店舗概要
- 現状課題
- 顧客・売上・発信の簡易診断
- 公式LINE運用の課題
- Lステップ導入要否
- 今月の優先施策
- 支援メニュー案
- 初期改善ロードマップ

---

## 6.2 月次支援フロー

### 6.2.1 目的

継続支援店舗に対して、毎月の成果確認、課題整理、次月施策提案を行う。

### 6.2.2 フロー

```text
月次データを取込/更新
↓
売上・予約・顧客状態を確認
↓
施策結果を確認
↓
AIが月次改善案を生成
↓
代理店が内容を編集
↓
店舗向け月次レポートを作成
↓
次月アクションを確定
↓
文案・対象者リストを作成
↓
店舗承認後に実行
```

### 6.2.3 月次レポート内容

| 項目 | 内容 |
|---|---|
| 月次サマリ | 売上、予約、新規、リピート、休眠の概要 |
| KPI推移 | 前月比較、目標比較 |
| 顧客状態 | 初回後、リピーター、休眠予備軍、休眠、VIP候補 |
| 実施施策 | LINE配信、SNS投稿、Google投稿、個別対応 |
| 施策結果 | 反応、返信、予約、来店、売上 |
| 課題 | 今月見えた課題 |
| 次月施策 | 優先アクション、対象、文案方向性 |
| 注意点 | 表現リスク、データ不足、同意・配信停止 |

---

## 6.3 LINE運用支援フロー

### 6.3.1 目的

公式LINEを活用した再来店・休眠復帰・アップセル施策を、代理店が支援する。

### 6.3.2 フロー

```text
施策目的を選択
↓
AIが対象者候補を抽出
↓
配信停止・同意未取得者を除外
↓
配信文を生成
↓
広告表現チェックを実行
↓
代理店が編集
↓
店舗へ承認依頼
↓
公式LINEまたはLステップ側で配信
↓
結果を記録
↓
次回改善案を生成
```

### 6.3.3 代理店が支援する内容

- 配信目的の整理
- 対象者条件の確認
- 外部ツール用タグ案の作成
- LINE文案の作成
- 表現リスクの確認
- 配信タイミングの提案
- 配信後の結果整理

---

## 6.4 Lステップ設計支援フロー

### 6.4.1 目的

LステップやL Messageの構築者が、タグ設計・シナリオ設計・改善提案を効率化する。

### 6.4.2 フロー

```text
店舗情報・顧客状態を整理
↓
施策目的を選択
↓
必要なセグメントをAIが提案
↓
外部ツール用の最小タグ案を作成
↓
初回後・休眠・アップセルなどのシナリオ案を作成
↓
Lステップ側で構築
↓
配信・シナリオ結果を取込/入力
↓
改善案を生成
```

### 6.4.3 出力内容

| 出力 | 内容 |
|---|---|
| タグ設計案 | 必要最小限のタグ名、用途、対象条件 |
| シナリオ案 | 初回後、休眠復帰、回数券更新、アップセルなど |
| 配信文案 | 各ステップで送る文案 |
| 分岐条件案 | 返信あり/なし、予約あり/なし、来店あり/なしなど |
| 注意点 | タグ肥大化、過剰配信、表現リスク |
| 改善案 | 配信結果をもとにした見直し案 |

### 6.4.4 初期での注意

本サービスはLステップの構築画面を置き換えない。

初期は、Lステップ構築者が設計に使うための以下の出力に留める。

- タグ設計案
- シナリオ設計案
- 配信文案
- 対象者条件
- CSV出力
- 改善レポート

---

↓
店舗承認
↓
投稿
↓
結果を記録

### 6.5.3 出力内容

- 1週間分のInstagram投稿テーマ

- 投稿カレンダー

## 8. 代理店向けAI機能

### 8.1 代理店提案AI

#### 目的

店舗診断結果をもとに、代理店が使える提案書・改善提案・月次報告を作成する。

#### 入力

- 店舗情報
- 業種
- エリア
- 利用中ツール
- 売上データ
- 顧客状態
- 発信状況
- 施策結果
- 店舗課題
- 代理店の支援メニュー

#### 出力

- 現状診断
- 課題整理
- 改善方針
- 提案施策
- 実行スケジュール
- 公式LINE/Lステップ利用方針
- 月次レポート文
- 店舗向け説明文

### 8.2 Lステップ要否診断AI

#### 目的

対象店舗に対して、公式LINEのみで運用可能か、Lステップ等の導入が必要かを判断支援する。

#### 判定観点

| 観点 | 内容 |
|---|---|
| 顧客数 | 配信対象が多く、手動運用が難しいか |
| セグメント数 | 複数の顧客状態・ニーズ別配信が必要か |
| シナリオ複雑度 | 初回後、休眠、アップセルなど自動分岐が必要か |
| 配信頻度 | 週次・月次で複数施策を回す必要があるか |
| 予約導線 | LINE上で予約・問合せ導線を強化したいか |
| 運用体制 | 店舗側が手動運用できるか |
| 予算 | Lステップ構築・運用費を許容できるか |

#### 出力

| 判定 | 意味 |
|---|---|
| 公式LINEのみで十分 | 手動運用・簡易タグで足りる |
| 本サービス + 公式LINE推奨 | 対象者・文案・施策設計を本サービスで補完すれば足りる |
| Lステップ等の併用推奨 | シナリオ配信や高度な自動化が必要 |
| 要ヒアリング | データ不足で判断できない |

### 8.3 複数店舗比較AI

#### 目的

代理店が担当する複数店舗を比較し、優先対応店舗や成功パターンを見つける。

#### 出力

- 売上改善が必要な店舗
- 休眠顧客が増えている店舗
- 施策実行率が低い店舗
- LINE配信反応が低い店舗
- 成功施策がある店舗
- 他店舗に横展開できる施策

### 8.4 レポート生成AI

#### 目的

月次報告・提案書・改善レポートを半自動生成する。

#### 必須出力

- 結論
- 今月の状態
- 主な課題
- 実施施策
- 結果
- 次月提案
- 注意点
- 店舗側に依頼すること

## 9. 承認・責任分界点

### 9.1 基本方針

代理店が作成した施策・文案・レポートであっても、顧客向け配信や外部公開投稿は店舗側の承認を前提とする。

AI提案や代理店提案は、最終判断の代替ではなく、意思決定支援として扱う。

### 9.2 承認が必要なもの

| 対象 | 承認者 | 理由 |
|---|---|---|
| 顧客向けLINE配信文 | 店舗オーナー/店長 | 顧客へ直接届くため |
| Instagram投稿文 | 店舗オーナー/店長 | 外部公開されるため |
| Google投稿文 | 店舗オーナー/店長 | 外部公開されるため |
| 口コミ返信文 | 店舗オーナー/店長 | 公開情報として残るため |
| キャンペーン文 | 店舗オーナー/店長 | 価格・条件誤認リスクがあるため |
| Lステップシナリオ案 | 店舗オーナー/店長 | 顧客体験に影響するため |
| 月次レポート | 代理店責任者/店舗 | 報告内容の正確性確認のため |

### 9.3 責任分界点

| 領域 | 本サービス | 代理店・コンサル | 店舗 |
|---|---|---|---|
| AI提案 | 提案支援、根拠表示、注意表示 | 内容確認、編集 | 最終判断 |
| 文案生成 | 文案生成、表現チェック | 編集、提案 | 承認、実行判断 |
| 配信実行 | 対象者・文案出力 | 配信準備支援 | 実行または実行許可 |
| 外部投稿 | 投稿文生成 | 投稿準備支援 | 承認、投稿判断 |
| 法令判断 | リスク警告 | 注意確認、必要に応じ専門家相談 | 最終責任 |
| データ入力 | 取込機能提供 | 入力支援 | 正確性確認 |
| 結果分析 | 分析支援 | 解釈・提案 | 実行判断 |

## 10. データ・プライバシー設計

### 10.1 代理店利用時の原則

- 店舗ごとに代理店アクセスを明示的に許可する
- 個人情報の閲覧可否を店舗単位で設定する
- 初期は集計レポート中心の支援を推奨する
- 顧客名・電話番号・メールのCSV出力は制限する
- 代理店向けレポートでは原則として個人名を出さない
- 代理店が担当外店舗を閲覧できないようにする
- 操作ログを必ず残す

### 10.2 データ出力制御

| 出力 | 制御方針 |
|---|---|
| 月次レポートPDF | 個人情報を除外した形式を標準にする |
| 提案書PDF | 店舗概要・集計情報中心にする |
| 顧客リストCSV | full_support以上、店舗許可時のみ |
| 対象者リストCSV | 顧客名を匿名化するオプションを用意 |
| AI相談ログ | 店舗単位で管理し、代理店横断利用は制限 |
| 匿名集計 | 個人・店舗が特定されない粒度に限定 |

### 10.3 代理店退任時の扱い

代理店が支援終了した場合、以下を行う。

| 対象 | 方針 |
|---|---|
| 店舗データ閲覧 | 権限停止 |
| 顧客情報 | アクセス不可 |
| 代理店作成レポート | 店舗側には残す。代理店側保持は契約に従う |
| 代理店独自テンプレート | 代理店側に残す |
| 操作ログ | システム側で保持 |
| 出力済みファイル | 契約・規約で扱いを明記 |

## 11. 代理店独自テンプレート

### 11.1 目的

代理店が自社ノウハウを活かし、業種別・目的別の提案テンプレートを作成できるようにする。

### 11.2 テンプレート種類

| 種類 | 内容 |
|---|---|
| 診断テンプレート | 初回診断の質問・評価項目 |
| 提案書テンプレート | 営業提案書の構成 |
| 月次レポートテンプレート | 月次報告の構成 |
| LINE施策テンプレート | 休眠復帰、初回後、アップセル等の施策 |
| Instagram投稿テンプレート | 投稿テーマ、文章構成、ハッシュタグ |
| Google投稿テンプレート | 地域検索向け投稿構成 |
| Lステップシナリオテンプレート | タグ・分岐・配信文案 |

### 11.3 初期方針

MVPでは、代理店独自テンプレートの管理画面は後回しでもよい。

初期は、システム標準テンプレートを提供し、運用上必要なものは設定ファイルまたは管理者設定で追加する。

将来的に代理店ごとのテンプレート管理を実装する。

## 12. 料金・プラン設計の考え方

### 12.1 代理店向けプラン候補

| プラン | 想定内容 |
|---|---|
| Agency Lite | 少数店舗、診断・レポート中心 |
| Agency Standard | 複数店舗、施策・文案・月次支援まで |
| Agency Pro | 独自テンプレート、複数担当者、詳細分析 |
| White Label | 代理店ブランドでの提供を検討 |

### 12.2 課金軸候補

| 課金軸 | 内容 |
|---|---|
| 担当店舗数 | 管理する店舗数に応じて課金 |
| 利用ユーザー数 | 代理店担当者数に応じて課金 |
| AI生成回数 | 文案・レポート・診断生成回数に応じて制限 |
| レポート出力数 | PDF・提案書出力数に応じて制限 |
| 外部連携数 | LINE、Instagram、Google等の連携数 |
| 独自テンプレート数 | 代理店独自テンプレートの利用数 |

### 12.3 初期判断

初期は複雑な従量課金にしすぎない。

まずは、以下のような単純な設計が現実的である。

```text
月額基本料
+ 管理店舗数
+ AI利用上限
```

## 13. MVP実装範囲

### 13.1 MVPで必須

| 機能 | 理由 |
|---|---|
| 代理店ユーザー権限 | 複数店舗支援に必須 |
| 店舗割当 | 担当店舗だけ見せるために必須 |
| 代理店ダッシュボード | 優先対応店舗を把握するため |
| 店舗診断 | 営業・初期支援に直結する |
| 提案書生成 | 代理店利用の価値が出やすい |
| 月次レポート生成 | 継続支援に必要 |
| 文案生成・承認依頼 | LINE/SNS支援に必要 |
| 個人情報閲覧制御 | 信頼性・法令対応上必須 |
| 監査ログ | 代理店利用では必須 |

### 13.2 MVPで後回しでもよい

| 機能 | 理由 |
|---|---|
| 独自テンプレート管理画面 | 初期は標準テンプレートで代替可能 |
| ホワイトラベル | 営業上魅力はあるが実装負荷が高い |
| 詳細な請求管理 | 初期は手動請求でも可能 |
| 複数担当者の詳細ワークフロー | 初期はシンプルな権限で十分 |
| 代理店横断ベンチマーク | データ蓄積後に実装すべき |
| 外部API自動連携 | 初期方針では不要 |
