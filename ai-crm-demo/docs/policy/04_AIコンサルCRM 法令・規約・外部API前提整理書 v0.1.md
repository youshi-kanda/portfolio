## 1. 本書の目的

本書は、AIコンサルCRMのシステム設計において、法令・外部サービス規約・外部API仕様・広告表現規制に関する前提条件を整理するものである。

本システムは、顧客データ、売上データ、予約・来店データ、LINE/SNS発信、エリア需要、AI相談履歴などを扱うため、単なる業務システムではなく、個人情報・広告表現・外部プラットフォーム制約の影響を強く受ける。

そのため、実装前に以下を明確にする。

- どのデータを取得できるか

- どのデータをAI分析に利用できるか

- どの情報を横断分析・二次活用できるか

- LINE、Instagram、Googleビジネスプロフィールなどの外部連携で何が可能か

- 美容、整体、ジムなどの業種で避けるべき広告表現は何か

- AI提案にどこまで責任を持たせるか

- どこから人間承認を必須にするか


## 2. 基本方針

### 2.1 設計上の原則

本システムでは、以下を基本方針とする。

1. 外部API連携は初期必須要件にしない

2. 初期はCSV、Googleスプレッドシート、手入力を中心にする

3. 顧客個人情報は店舗内利用を原則とする

4. 横断分析は匿名化・集計化したデータのみを対象にする

5. AI提案には根拠、信頼度、注意点を表示する

6. 顧客への配信・外部発信は人間承認を基本にする

7. 法令・規約に関わる判断は、最終的に専門家確認を必要とする

8. 外部API仕様は実装直前に公式ドキュメントで再確認する


### 2.2 初期実装の安全方針

初期段階では、以下の構成を推奨する。

| 領域               | 初期方針                | 理由                 |
| ---------------- | ------------------- | ------------------ |
| LINE連携（Phase 1〜4） | 文案・対象者リスト出力のみ（配信は手動） | API・料金・同意管理の負荷を下げる |
| LINE連携（Phase 5〜） | 承認済み文案からBroadcast/Multicast/ステップ配信を実行 | 同意管理・人間承認・監査ログを必須とした上で実装 |
| Instagram連携      | 投稿文案生成まで            | API権限・審査・仕様制約を避ける  |
| Googleビジネスプロフィール | 投稿案・分析メモ出力まで        | APIアクセス・割当制約を避ける   |
| 予約/POS連携         | CSV取込を基本            | サービスごとの差異が大きいため    |
| AI提案             | 意思決定支援として扱う         | 成果保証・法的判断の誤認を避ける   |
| データ二次利用          | 匿名化・集計化を前提          | 店舗・顧客の不信を避ける       |

## 3. 個人情報・データ活用前提

### 3.1 扱う情報の分類

|分類|例|取扱方針|
|---|---|---|
|個人情報|氏名、電話番号、メール、LINE userId、詳細な顧客メモ|店舗内利用が原則|
|顧客行動情報|来店日、予約、キャンセル、購入、配信反応|店舗改善に利用。横断利用は匿名・集計化|
|店舗情報|売上、客単価、施策結果、メニュー構成|店舗内分析に利用。横断利用は店舗特定不可にする|
|AI相談情報|店舗の相談内容、AI提案、採用結果|提案改善に利用。ただし機密情報に注意|
|匿名集計情報|業種別平均、地域別傾向、施策成功率|ベンチマーク・新サービス開発に利用可能|

### 3.2 個人情報の利用目的

初期利用規約・プライバシーポリシーでは、少なくとも以下を明示する必要がある。

- 顧客管理のため

- 予約・来店・購入履歴の管理のため

- 店舗の集客・再来店・顧客フォロー改善のため

- AIによる分析・提案・文案生成のため

- 施策結果の分析・改善のため

- サービス品質向上のため

- 匿名化・集計化したデータによる統計分析のため


### 3.3 匿名加工情報・仮名加工情報・統計情報の区分

本システムでは、以下を明確に区別する。

|区分|内容|本システムでの扱い|
|---|---|---|
|個人情報|特定個人を識別できる情報|店舗内利用。権限管理・削除対応対象|
|仮名加工情報|他情報と照合しない限り個人識別できないよう加工した情報|内部分析向け。第三者提供は慎重に扱う|
|匿名加工情報|特定個人を識別できず、復元できないよう加工した情報|横断分析・二次活用の候補|
|統計情報|個人に関する情報に該当しない集計結果|ベンチマークや市場分析に活用しやすい|

### 3.4 データ二次利用の基本設計

コアデータを将来開発やサービス改善に活かす場合、以下の設計が必要である。

|利用対象|利用可否|条件|
|---|---|---|
|個別顧客情報|原則不可|店舗内支援目的のみ|
|個別店舗の売上・施策情報|原則不可|店舗の同意なしに他社提供しない|
|匿名化・集計化データ|利用可能|個人・店舗が特定されないこと|
|業種別平均データ|利用可能|十分な件数と匿名化が前提|
|地域別需要データ|利用可能|個別店舗特定を避ける|
|AI相談傾向|利用可能|機密情報・固有名詞の除去が前提|

## 4. LINE連携前提

### 4.1 LINE Messaging APIで可能なこと

LINE Messaging APIでは、将来的に以下のような連携が想定できる。

- Webhookによるイベント受信

- userIdの取得

- Pushメッセージ

- Multicastメッセージ

- Narrowcastメッセージ

- Broadcastメッセージ

- Audienceの利用

- メッセージクリック・インプレッションを使ったAudience作成

- リッチメニュー連携

- クーポン等の一部API活用


### 4.2 Audience作成の制約

Messaging APIで作成可能なAudienceには制限がある。

作成可能な代表例：

- userIdアップロードAudience

- メッセージクリックAudience

- メッセージインプレッションAudience


Messaging APIから直接作成できない代表例：

- チャットタグAudience

- 友だち追加経路Audience

- 予約Audience

- リッチメニュークリックAudience

- リッチメニュー表示Audience

- LINE TagのWebトラフィックAudience

- アプリイベントAudience

- 動画視聴Audience

- 画像クリックAudience


### 4.3 設計への影響

上記制約により、「公式LINE側のタグ設定を完全に不要にする」設計は初期段階では危険である。

本システムでは、以下の方針を採る。

|フェーズ|方針|
|---|---|
|Phase 1|対象者リスト、配信文、施策案を出力する|
|Phase 2|LINE userId連携、配信結果の一部取得を検討する|
|Phase 3|Messaging APIを使った半自動・自動配信を検討する|

### 4.4 LINE料金への影響

LINE配信は、配信通数やプランによって費用が変わる。

そのため、将来的に自動配信を行う場合は、以下の機能が必要になる。

- 月間配信通数の見積もり

- 配信対象者数の確認

- 配信前の費用目安表示

- 一斉配信ではなく対象者を絞る設計

- 配信頻度の制御

- ブロック・配信停止状態の管理


### 4.5 LINE連携の初期判断

初期実装では、LINE自動配信は対象外とし、以下に留める。

- LINE配信用文案生成

- 配信対象者リスト出力

- 配信目的・優先度の提案

- 配信後結果の手入力またはCSV取込


## 5. Instagram連携前提

### 5.1 初期方針

Instagramは、初期段階ではAPI連携を前提にしない。

理由：

- Instagram Graph APIはアカウント種別、権限、審査に制約がある

- 投稿・インサイト取得に必要な権限確認が必要

- ユーザーのInstagram運用状況にばらつきがある

- 初期価値は投稿文・投稿テーマ生成だけでも出せる


### 5.2 初期機能

- Instagram投稿案生成

- 1週間分の投稿テーマ提案

- ハッシュタグ案

- リール台本案

- 投稿カレンダー案

- 投稿後の結果を手入力


### 5.3 将来機能

- Instagramインサイト取得

- 投稿実績の取得

- 反応率分析

- 投稿テーマ別の効果分析

- LINE/予約データとの相関分析


## 6. Googleビジネスプロフィール連携前提

### 6.1 取得できる可能性がある情報

GoogleビジネスプロフィールのPerformance APIでは、ビジネスプロフィールのパフォーマンスレポート、日次・月次指標、検索またはマップでビジネスを見つけるために使われた検索キーワードなどを取得できる可能性がある。

ただし、APIを有効化しても割当が0の場合は、GBP APIアクセス申請が必要になる可能性がある。

### 6.2 初期方針

初期は自動API連携を必須にしない。

初期機能：

- Googleビジネスプロフィール投稿文生成

- 口コミ返信案生成

- エリア需要メモの手入力

- 検索語句や閲覧数の手入力

- 月次レポートへの反映


### 6.3 将来機能

- Performance API連携

- 検索キーワード分析

- Googleマップ経由の流入分析

- 口コミ内容の分類

- 投稿と予約数の相関分析


## 7. 予約システム・POS連携前提

### 7.1 初期方針

予約システム・POSはサービスごとに仕様差が大きいため、初期はCSV取込を基本とする。

対象になり得るデータ：

- 顧客一覧

- 予約履歴

- 来店履歴

- キャンセル履歴

- メニュー履歴

- 売上履歴

- 回数券・契約情報


### 7.2 将来連携候補

- RESERVA

- STORES予約

- Airリザーブ

- リザービア

- SALON BOARD

- Googleカレンダー

- POSレジ

- 会計システム


### 7.3 注意点

- API公開状況がサービスごとに異なる

- CSVの項目名が統一されない

- 顧客IDの名寄せが必要

- 同一顧客が複数経路で登録される可能性がある

- 予約データと売上データが分離している場合がある


## 8. 広告表現・業種別規制前提

### 8.1 共通で注意すべき表現

本システムは発信文を生成するため、以下の表現を制御する必要がある。

- 効果を断定する表現

- 実際より著しく優良・有利と誤認させる表現

- 根拠のないNo.1表現

- 過度なビフォーアフター訴求

- 医療的効果を示す表現

- 確実な痩身・改善・治癒を保証する表現

- 口コミや体験談の不適切利用

- PR表記なしの広告・案件投稿

- 過度な不安訴求

- 期間限定・残りわずか等の虚偽表示


### 8.2 景品表示法・ステルスマーケティング

以下に注意する。

- 実際より著しく良いと誤認される表示を避ける

- 価格・キャンペーン・割引の条件を明確にする

- 口コミ、紹介、インフルエンサー投稿では広告であることが分かる表示を検討する

- PR、広告、提供、モニターなどの表示が必要なケースを管理する

- AI生成文が誇大表示にならないようチェックする


### 8.3 エステ・美容サロンでの注意

- 痩せる、治る、消える、永久に、必ず、即効などの断定表現を避ける

- 医療行為と誤認される表現を避ける

- 効果には個人差がある旨を必要に応じて補足する

- ビフォーアフターや体験談の使い方に注意する

- 薬機法・景品表示法に抵触し得る表現を制御する


### 8.4 整体・接骨院・鍼灸院での注意

- 疾病の治癒や医学的効果の断定を避ける

- 医療広告や柔道整復・あはき関連の規制に注意する

- 保険適用に関する誤認を避ける

- 症状改善を保証する表現を避ける

- お客様の声や症例表現の扱いに注意する


### 8.5 パーソナルジムでの注意

- 必ず痩せる、何kg痩せる保証などの断定を避ける

- 極端な身体変化を保証する表現を避ける

- 健康・栄養・サプリメント表現に注意する

- ビフォーアフター表現には条件や個人差への配慮が必要


## 9. AI利用前提

### 9.1 AIの位置づけ

AIは、以下の役割を担う。

- 分析補助

- 相談相手

- 施策提案

- 発信文生成

- 改善案作成

- データ整理


AIは、以下を担わない。

- 法的判断の代替

- 医療判断の代替

- 売上向上の保証

- 自動的な外部発信の最終決定

- 顧客への重要連絡の完全自動化


### 9.2 AI出力に必須の項目

AI提案には以下を含める。

- 提案内容

- 対象

- 目的

- 根拠

- 参照データ

- 信頼度

- 注意点

- 実行手順

- 人間確認の必要有無


### 9.3 AI出力の承認ルール

|出力内容|承認要否|
|---|---|
|ダッシュボード上の分析コメント|承認不要|
|内部向けアクション提案|承認不要または簡易承認|
|顧客へのLINE配信文|承認必須|
|Instagram投稿文|承認必須|
|Googleビジネス投稿文|承認必須|
|キャンペーン文|承認必須|
|法令・医療・効果に関わる表現|要注意・専門家確認推奨|

## 10. プライバシーポリシー・利用規約で明記すべきこと

### 10.1 プライバシーポリシー

以下を明記する必要がある。

- 取得する情報

- 利用目的

- AI分析への利用

- 外部サービス連携

- 第三者提供の有無

- 委託先の扱い

- 匿名化・集計化データの利用

- データ削除・開示請求への対応

- 安全管理措置

- 問い合わせ窓口


### 10.2 利用規約

以下を明記する必要がある。

- AI提案は成果を保証しないこと

- 法務・医療・広告審査の最終判断は利用者側が行うこと

- 外部サービスの仕様変更により機能制限が生じ得ること

- データ入力の正確性は利用者側にも責任があること

- 禁止用途

- アカウント停止条件

- データ利用範囲

- 匿名集計データの活用方針


## 11. 実装フェーズ別の法令・API対応

|フェーズ|主な機能|法令・API対応|
|---|---|---|
|Phase 1|CSV取込、AI診断、文案生成、アクション提案|プライバシーポリシー、AI注意表示、広告表現チェック|
|Phase 2|Googleスプレッドシート連携、施策結果管理|外部連携同意、権限管理、データ削除対応|
|Phase 3|LINE userId連携、半自動配信|LINE API仕様確認、配信同意、配信停止管理|
|Phase 4|Instagram/Google API連携|Meta/Google API審査、権限、割当確認|
|Phase 5|横断分析・ベンチマーク|匿名化・集計化、最小集計数、規約明示|

## 12. 現時点の設計判断

現時点では、以下の判断を採る。

1. 初期は外部APIに依存しない

2. LINE自動配信は初期対象外

3. Instagram、Googleビジネスプロフィールも初期は文案生成中心

4. 予約・売上データはCSV/スプレッドシート取込を基本にする

5. AI提案には根拠・信頼度・注意点を必須表示する

6. 顧客への発信は人間承認を必須にする

7. コアデータの横断活用は匿名化・集計化を前提にする

8. 法令・広告表現に関わる領域は専門家確認を前提にする
