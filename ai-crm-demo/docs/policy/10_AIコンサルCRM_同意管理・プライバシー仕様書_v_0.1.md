# AIコンサルCRM 同意管理・プライバシー仕様書 v0.1

## 1. 本書の目的

本書は、AIコンサルCRMにおける顧客同意、配信停止、個人情報管理、AI分析利用、匿名集計データ活用、削除・開示請求対応に関する仕様を定義するものである。

本サービスは、個人店・小規模店舗が公式LINE、Instagram、Googleビジネスプロフィール、予約/来店履歴、売上データ、接客メモ、AI相談履歴などを活用し、集客・再来店・顧客フォロー・売上改善を行うためのAIコンサルCRMである。

そのため、以下を明確にする必要がある。

- 顧客からどの同意を取得するか
- 同意状態をどこで管理するか
- 配信停止者をどのように除外するか
- 顧客データをAI分析に使う条件
- 店舗データや施策データを匿名集計・横断分析に使う条件
- 代理店・コンサルが閲覧できる個人情報の範囲
- 削除、開示、訂正、利用停止要求への対応
- プライバシーポリシー・利用規約に明記すべき事項

---

## 2. 基本方針

### 2.1 設計思想

本サービスでは、顧客データを売上改善に活用する一方で、個人情報の過剰取得・過剰利用を避ける。

特に以下を基本方針とする。

| 方針 | 内容 |
|---|---|
| 目的限定 | 顧客管理、予約/来店管理、集客・再来店改善、AI提案に必要な範囲で利用する |
| 最小取得 | 氏名、電話番号、メール、LINE userIdなどは必要な場合のみ取得する |
| 店舗内利用原則 | 個人情報は原則として該当店舗内の改善支援に利用する |
| 配信停止優先 | 配信停止・同意未取得の顧客は対象者抽出から除外する |
| 人間承認 | 顧客に届くLINE文・メール文・外部投稿文は人間承認を必須にする |
| 匿名集計前提 | 横断分析やベンチマークには匿名化・集計化したデータのみを使う |
| 権限分離 | 代理店・支援者が閲覧できる個人情報を店舗単位・権限単位で制御する |
| 監査可能性 | 同意変更、配信対象出力、AI利用、CSV出力などはログを残す |

### 2.2 初期実装での安全方針

初期は外部API連携や自動配信を必須にしない。

| 領域 | 初期方針 |
|---|---|
| 公式LINE配信 | 自動配信ではなく、文案生成・対象者リスト出力まで |
| 配信対象抽出 | customer_consents を参照し、配信停止者・同意未取得者を除外 |
| AI分析 | 店舗内改善目的に限定し、参照データ・根拠・信頼度を表示 |
| 外部発信 | 承認済みの文案のみ利用可能にする |
| 代理店利用 | 個人情報閲覧可否を店舗ごとに明示管理 |
| 横断分析 | MVPでは本番機能化せず、設計上の前提に留める |

## 3. 管理する同意の種類

### 3.1 同意区分

本サービスでは、少なくとも以下の同意・許可状態を管理する。

| 同意区分 | 内容 | 主な利用場面 |
|---|---|---|
| LINE連絡同意 | 公式LINEまたはLINE関連ツールで連絡してよいか | LINE配信、個別LINE連絡 |
| メール連絡同意 | メールで連絡してよいか | メール配信、予約案内 |
| SMS連絡同意 | SMSで連絡してよいか | リマインド、重要連絡 |
| 分析利用同意 | 顧客データを店舗内の分析・AI提案に使ってよいか | 顧客状態判定、休眠判定、AI提案 |
| 外部連携同意 | 外部ツール連携に必要な範囲でデータを使ってよいか | LINE userId連携、予約/POS連携 |
| 配信停止状態 | マーケティング配信を停止しているか | 対象者除外 |
| 匿名集計利用許容 | 匿名化・集計化したデータ活用を許容するか | 業種別ベンチマーク、サービス改善 |

### 3.2 customer_consents で管理する項目

DB設計では、顧客ごとの同意状態を `customer_consents` で管理する。

| 項目 | 内容 |
|---|---|
| customer_id | 対象顧客 |
| store_id | 所属店舗 |
| contact_line_allowed | LINE連絡可否 |
| contact_email_allowed | メール連絡可否 |
| contact_sms_allowed | SMS連絡可否 |
| analysis_allowed | AI分析・店舗内分析利用可否 |
| external_integration_allowed | 外部ツール連携可否 |
| is_unsubscribed | 配信停止状態 |
| unsubscribed_at | 配信停止日時 |
| consent_source | 同意取得元 |
| consented_at | 同意取得日時 |
| updated_at | 更新日時 |

### 3.3 同意状態の初期値

初期取込時の同意状態は、取り込み元データの根拠に応じて慎重に扱う。

| 取込元 | 初期設定案 | 注意点 |
|---|---|---|
| 公式LINE友だち | LINE連絡可。ただしマーケ配信同意の扱いは運用確認 | 友だち追加だけで何でも送ってよいとは限らない |
| 予約システムCSV | 分析利用は店舗内目的として可。ただし外部配信は別確認 | 予約時の規約・同意文言を確認する |
| 紙カルテ/Excel | 分析利用・連絡利用ともに要確認 | 古い顧客情報は特に慎重に扱う |
| メールリスト | メール同意の根拠がある場合のみ可 | オプトアウト履歴を確認する |
| 手入力 | 入力時に同意根拠を選択 | 担当者任せにしすぎない |

## 4. 配信停止・除外ルール

### 4.1 配信対象抽出の必須条件

LINE配信対象者を抽出する場合は、最低限以下を満たす必要がある。

```text
customer.status = active
AND customer_consents.contact_line_allowed = true
AND customer_consents.is_unsubscribed = false
```

メールの場合は `contact_email_allowed`、SMSの場合は `contact_sms_allowed` を参照する。

### 4.2 除外すべき顧客

| 除外理由 | 内容 |
|---|---|
| 配信停止 | is_unsubscribed = true |
| 同意未取得 | 該当チャネルの連絡同意がない |
| 顧客削除済み | customer.status = deleted |
| クレーム注意 | 注意タグまたは接客メモで配信不可と判断 |
| 個別対応中 | 一斉配信より個別対応が適切 |
| 法令・表現上のリスク | 特定訴求が不適切な可能性 |

### 4.3 除外者リストの表示

セグメント/対象者整理画面では、対象者数だけでなく除外者数と理由を表示する。

| 表示項目 | 内容 |
|---|---|
| 除外人数 | 配信対象から外した人数 |
| 除外理由 | 配信停止、同意未取得、手動除外など |
| 個別確認要否 | 個別対応が必要か |
| 再同意取得候補 | 同意状態が不明な顧客に確認が必要か |

### 4.4 配信停止の反映タイミング

配信停止は、可能な限り即時反映を原則とする。

| 操作 | 反映内容 |
|---|---|
| 顧客が配信停止を希望 | is_unsubscribed = true |
| 店舗スタッフが配信停止登録 | 即時除外対象にする |
| 外部ツールから停止情報を取込 | 取込時点で更新 |
| 誤登録の解除 | 権限者のみ変更可能。audit_logsに記録 |

## 5. AI分析利用の同意設計

### 5.1 AI分析に利用するデータ

AI分析では、必要に応じて以下のデータを参照する。

| データ | 利用例 |
|---|---|
| 顧客状態 | 休眠、初回後、VIP候補などの判定 |
| 来店履歴 | 最終来店日、来店回数、来店周期の分析 |
| 売上履歴 | LTV、客単価、アップセル候補の分析 |
| メニュー履歴 | 興味・悩み・次回提案の推定 |
| 接客メモ | 顧客ニーズ、注意点、阻害要因の整理 |
| 配信・反応履歴 | 関心テーマ、返信、予約転換の把握 |
| 施策結果 | 次回改善案、効果検証 |

### 5.2 AI分析利用の条件

| 条件 | 内容 |
|---|---|
| 店舗内改善目的 | 顧客管理、再来店、フォロー改善、売上改善の範囲で利用 |
| 必要最小限 | 相談内容に必要なデータのみAIに渡す |
| 同意状態確認 | analysis_allowed が false の顧客は個別分析対象から除外する |
| 出力根拠表示 | AI提案には根拠・参照データ・信頼度を表示する |
| 人間確認 | 顧客向け文案や外部発信は承認必須 |

### 5.3 AIに渡すべきでない情報

以下は、原則としてAI入力に渡さない、またはマスキングする。

| 情報 | 方針 |
|---|---|
| 不要な電話番号・メール | 文案生成や施策提案に不要なら渡さない |
| 詳細住所 | 商圏分析に必要な粒度までに留める |
| センシティブな接客メモ | 必要時のみ要約・マスキングして利用 |
| クレーム詳細 | 個人特定情報を除いた要約にする |
| 医療・健康に関する詳細情報 | 業種上必要な場合でも慎重に扱う |
| 決済情報 | AI分析には原則不要 |

### 5.4 AI出力に必須の表示

AI提案には以下を表示する。

| 項目 | 内容 |
|---|---|
| 提案内容 | 何をすべきか |
| 対象 | どの顧客・セグメント・チャネルか |
| 目的 | 何を改善する施策か |
| 根拠 | 判断理由 |
| 参照データ | 売上、来店履歴、顧客状態など |
| 信頼度 | 高・中・低 |
| 注意点 | データ不足、表現リスク、過剰配信など |
| 人間確認要否 | 承認が必要か |

## 6. 代理店・コンサル利用時のプライバシー設計

### 6.1 基本方針

代理店・コンサルは、店舗を支援するために必要な範囲でのみデータを閲覧できる。

| 方針 | 内容 |
|---|---|
| 店舗単位権限 | 支援先店舗ごとに権限を付与する |
| 最小権限 | 初期は個人情報を見せず、集計・診断中心を推奨する |
| 出力制限 | CSV/PDF出力の可否を権限で制御する |
| 個人情報閲覧管理 | can_view_personal_data で明示制御する |
| 操作ログ | 閲覧、編集、出力、レポート作成を監査可能にする |

### 6.2 代理店権限レベル

| 権限レベル | 内容 | 個人情報閲覧 |
|---|---|---|
| view_report | 集計レポート閲覧のみ | 原則不可 |
| edit_campaign | 施策・文案作成、対象者数確認 | 原則不可。必要時のみ一部可 |
| full_support | 顧客詳細、施策、レポートまで支援 | 店舗許可がある場合のみ可 |

### 6.3 代理店向けレポートの個人情報除外

代理店向け提案書・月次レポートでは、原則として個人名・電話番号・メールアドレスを含めない。

| レポート項目 | 推奨表示 |
|---|---|
| 休眠顧客 | 人数、傾向、推奨施策 |
| 初回後フォロー対象 | 人数、条件、文案 |
| VIP候補 | 人数、LTV帯、対応方針 |
| 施策結果 | 対象人数、反応数、予約数、売上 |
| 個別対応候補 | 顧客IDの匿名表示または店舗内のみ表示 |

## 7. 匿名集計・横断分析の設計

### 7.1 基本方針

本サービスで蓄積されるデータは、将来的に業種別テンプレート改善、地域需要分析、新サービス開発に活用できる。

ただし、横断分析では個人・店舗が特定されないようにする。

### 7.2 利用可能なデータ

| データ | 利用可否 | 条件 |
|---|---|---|
| 個別顧客情報 | 原則不可 | 店舗内支援目的に限定 |
| 個別店舗の売上情報 | 原則不可 | 店舗同意なしに他社提供しない |
| 顧客状態分布 | 可能 | 個人・店舗が特定されない集計 |
| 施策成功率 | 可能 | 同種施策を十分な件数で集計 |
| 業種別平均指標 | 可能 | 最小店舗数・最小件数を満たす |
| 地域別ニーズ | 可能 | 店舗特定を避けた粒度で集計 |
| AI相談傾向 | 可能 | 固有名詞・機密情報を除去 |

### 7.3 最小集計数の初期案

| 集計種別 | 最小件数案 |
|---|---|
| 顧客単位の傾向 | 50件以上 |
| 業種別ベンチマーク | 同カテゴリ5店舗以上 |
| 施策成功パターン | 同種施策10件以上 |
| 地域別ニーズ | 個別店舗が推測されない粒度で集計 |

### 7.4 匿名集計データの利用目的

プライバシーポリシー・利用規約では、匿名化・集計化したデータを以下に利用する可能性を明記する。

- サービス品質向上
- 業種別テンプレート改善
- 業種別ベンチマーク作成
- 地域需要分析
- 施策効果の傾向分析
- 新機能・新サービス開発

## 8. 開示・訂正・削除・利用停止要求

### 8.1 対応する要求種別

| 要求 | 内容 |
|---|---|
| 開示 | 保有している個人情報の開示 |
| 訂正 | 誤った個人情報の修正 |
| 削除 | 顧客情報の削除またはマスキング |
| 利用停止 | 分析利用、配信利用、外部連携利用の停止 |
| 配信停止 | マーケティング配信の停止 |

### 8.2 data_requests で管理する項目

| 項目 | 内容 |
|---|---|
| request_type | disclosure / correction / deletion / suspension |
| customer_id | 対象顧客 |
| requested_by_name | 申請者名 |
| requested_by_contact | 連絡先 |
| status | received / verifying / completed / rejected |
| response_note | 対応メモ |
| requested_at | 申請日時 |
| completed_at | 完了日時 |

### 8.3 削除要求時の対応案

| データ | 対応案 |
|---|---|
| 氏名 | 削除または匿名化 |
| 電話番号 | 削除 |
| メールアドレス | 削除 |
| LINE userId | 削除または無効化 |
| 接客メモ | 個人特定部分を削除、必要に応じて全文削除 |
| 予約/来店履歴 | 個人IDを外して統計情報化を検討 |
| 売上履歴 | 個人IDを外して集計値として残すことを検討 |
| AI相談ログ | 個人情報を含む場合はマスキング |
| 施策結果 | 個人単位では削除、集計値は保持を検討 |

### 8.4 削除時の注意

- 法令上・会計上・契約上保持が必要なデータがある場合は、完全削除できない可能性がある
- 顧客本人確認を行ってから対応する
- 削除済み顧客を将来の配信対象に含めない
- 削除・マスキング処理は audit_logs に記録する
- AIログやレポート内に個人情報が残っていないか確認する

## 9. 監査ログ設計

### 9.1 監査対象操作

以下の操作は `audit_logs` に記録する。

| 操作 | 理由 |
|---|---|
| 顧客情報の閲覧 | 個人情報アクセス管理 |
| 顧客情報の編集 | 誤更新・不正更新の追跡 |
| 顧客情報の削除/マスキング | 削除要求対応の証跡 |
| 同意状態の変更 | 配信・分析利用の正当性確認 |
| 配信対象リスト出力 | 誤配信・不正持ち出し防止 |
| CSV/PDF出力 | 個人情報持ち出し管理 |
| AI提案生成 | 参照データと提案責任の確認 |
| 文案承認 | 外部発信の責任者確認 |
| 代理店権限変更 | 支援者アクセス管理 |

### 9.2 ログ保存項目

| 項目 | 内容 |
|---|---|
| user_id | 操作者 |
| store_id | 対象店舗 |
| action | 操作種別 |
| target_type | 対象種別 |
| target_id | 対象ID |
| before_snapshot | 変更前 |
| after_snapshot | 変更後 |
| ip_address | IPアドレス |
| user_agent | 利用環境 |
| created_at | 操作日時 |

## 11. プライバシーポリシーに明記すべき事項

### 11.1 取得する情報

- 店舗情報
- 顧客基本情報
- 予約・来店履歴
- 売上・購入履歴
- 問い合わせ・接客メモ
- 配信・発信・反応履歴
- AI相談内容
- システム利用ログ
- 外部サービス連携により取得する情報

### 11.2 利用目的

- 顧客管理のため
- 予約・来店・購入履歴の管理のため
- 店舗の集客・再来店・顧客フォロー改善のため
- AIによる分析・提案・文案生成のため
- 施策結果の分析・改善のため
- サービス品質向上のため
- 匿名化・集計化した統計分析のため
- 外部サービス連携機能の提供のため
- 不正利用防止・セキュリティ確保のため

### 11.3 第三者提供・委託

以下を明記する。

- 原則として個人情報を第三者に提供しないこと
- サービス提供に必要な範囲でクラウド、AI API、メール配信、分析基盤等の委託先を利用する可能性
- 外部連携時にLINE、Meta、Google、予約システム等へデータが連携される可能性
- 匿名化・集計化した情報は個人・店舗が特定されない形で活用する可能性

### 11.4 顧客の権利

- 開示請求
- 訂正請求
- 削除請求
- 利用停止請求
- 配信停止
- 問い合わせ窓口

## 12. 利用規約に明記すべき事項

| 項目 | 内容 |
|---|---|
| AI提案の位置づけ | AI提案は意思決定支援であり、成果を保証しない |
| 最終判断 | 法務、医療、広告審査、配信判断は利用者が確認する |
| データ入力責任 | 入力データの正確性は利用者にも責任がある |
| 同意取得責任 | 顧客への連絡・分析利用に必要な同意は店舗側でも適切に管理する |
| 禁止用途 | 不正取得データの利用、無断配信、誇大広告、差別的利用など |
| 外部サービス制約 | LINE、Instagram、Google等の仕様変更で機能制限が起こり得る |
| 匿名集計利用 | 匿名化・集計化データをサービス改善等に利用する可能性 |
| アカウント停止 | 規約違反、不正利用、重大な苦情がある場合の停止条件 |

## 14. MVPで必須の実装項目
