# AIコンサルCRM Phase1開発スコープ確定書 v0.1

## 1. 本書の目的

本書は、AIコンサルCRMのPhase1開発において、実装する範囲・実装しない範囲・開発順序・完了条件を明確にするための実装合意書である。

本プロジェクトは、VSCode + Claude Code を用いて開発を進める方針である。

そのため、既存の企画書・仕様書をすべて一度に実装対象にするのではなく、Claude Codeが迷わず実装できるように、Phase1で作る範囲を明確に固定する。

Phase1の目的は、以下である。

```text
店舗データを登録する
↓
顧客・予約/来店・売上データをCSVで取り込む
↓
顧客状態を判定する
↓
ダッシュボードで現状を可視化する
↓
AI診断または診断モックで今週のアクションを表示する
```

---

## 2. Phase1の位置づけ

### 2.1 Phase1の目的

Phase1は、AIコンサルCRMの最小動作版である。

この段階では、LINE自動配信やLステップ連携ではなく、以下を検証する。

- 顧客データを安全に登録・管理できるか
- CSV取込で実店舗データを扱えるか
- 顧客状態をルールベースで判定できるか
- 店舗が現状課題をダッシュボードで把握できるか
- AI診断または診断モックで次アクションを提示できるか

### 2.2 Phase1の成功条件

Phase1の成功条件は、以下である。

> エステサロンのサンプル店舗データを登録し、顧客CSV・予約/来店CSV・売上CSVを取り込み、顧客状態と基本KPIを表示し、今週の改善アクション候補を出せる状態。

### 2.3 Phase1で検証しないこと

Phase1では、以下は検証対象にしない。

- LINE配信の自動化
- Lステップとの直接連携
- SNS自動投稿
- Googleビジネスプロフィール自動連携
- 高度な代理店管理
- 決済・請求
- 本格予約管理
- 完全なAI自動コンサル

| エディタ | VSCode |
| AI開発支援 | Claude Code |
| バージョン管理 | Git / GitHub |
| 開発単位 | 小さなタスク単位で実装 |
| 実装方針 | Phase1縦切り優先 |
| 仕様参照 | CLAUDE.md と docs 配下を優先 |

### 3.2 Claude Code利用方針

Claude Codeには、巨大な仕様書全体を一括で実装させない。

以下の単位で依頼する。

```text
1タスク = 1機能または1画面または1API
```

例：

```text
P1-011 顧客CSV取込のバリデーションを実装してください。
対象ファイルは imports app 配下です。
Phase1範囲外のLINE連携やAI連携は実装しないでください。
```

### 3.3 Claude Codeに必ず参照させるファイル

| ファイル | 用途 |

## 5. Phase1で実装しない機能

Phase1では、以下を実装しない。

| 機能 | 理由 |
|---|---|
| LINE Messaging API自動配信 | 同意・料金・誤配信リスクが高い |
| LINE Webhook | userId連携やイベント処理は次フェーズ |
| LステップAPI連携 | 外部仕様依存が大きい |
| L Message API連携 | 外部仕様依存が大きい |
| Instagram Graph API | 権限・審査が必要 |
| Google Business Profile API | API割当・申請が必要 |
| 予約システムAPI連携 | サービスごとの差異が大きい |
| POS API連携 | 連携先ごとの差異が大きい |
| 本格予約管理 | 本サービスの初期価値ではない |
| 決済・請求管理 | MVP検証後でよい |
| 代理店複数店舗管理 | Phase4以降で検証 |
| ホワイトラベル | 代理店展開後でよい |
| 高度なAIコンサルチャット | Phase2以降で強化 |
| 文案生成・承認管理 | Phase2で実装 |
| セグメント対象者CSV出力 | Phase2で実装 |
| 月次レポート生成 | Phase3で実装 |

## 9. Phase1顧客状態判定ルール

### 9.1 初期判定対象

Phase1では、以下の顧客状態のみ判定する。

| 顧客状態 | 判定条件案 |
|---|---|
| 新規リード | 顧客登録あり、来店履歴なし、未来予約なし |
| 初回予約済 | 来店履歴なし、未来予約あり |
| 初回来店後 | 来店回数 = 1、次回予約なし、最終来店日から30日以内 |
| 2回目来店前 | 来店回数 = 1、未来予約あり |
| リピーター | 来店回数 >= 2、最終来店日から45日未満 |
| 休眠予備軍 | 最終来店日から45〜89日、次回予約なし |
| 休眠顧客 | 最終来店日から90日以上、次回予約なし |
| VIP候補 | 来店回数 >= 6、または累計売上が一定以上 |

### 9.2 Phase1では判定しないもの

以下はPhase2以降でよい。

- 詳細な推定ニーズ
- 行動阻害要因のAI推定
- アップセル候補の高度判定
- 回数券更新候補の詳細判定
- 口コミ依頼候補
- 顧客別文案生成

### 9.3 来店周期初期値

エステサロン向けPhase1では、以下を初期値とする。

```text
標準来店周期：30日
休眠予備軍：45日以上
休眠顧客：90日以上
```

店舗設定で将来的に変更可能にする。

## 10. Phase1 CSV取込範囲

### 10.1 取込対象

Phase1では、以下3種を必須とする。

| CSV | 必須項目 | 用途 |
|---|---|---|
| 顧客CSV | 顧客IDまたは氏名/電話等 | 顧客基本情報作成 |
| 予約/来店CSV | 顧客識別子、予約日/来店日、状態 | 来店回数・休眠判定 |
| 売上CSV | 顧客識別子、売上日、金額 | LTV・客単価判定 |

### 10.2 Phase1で対応する文字コード

| 文字コード | 対応 |
|---|---|
| UTF-8 BOM付き | 必須 |
| UTF-8 BOMなし | 必須 |
| Shift_JIS / CP932 | できればPhase1で対応。難しければ早期追加 |

### 10.3 Phase1で必要なCSV機能

- CSVアップロード
- ヘッダー読み取り
- 文字コード判定
- 項目マッピング
- 取込前プレビュー
- 必須項目チェック
- 日付形式チェック
- 金額形式チェック
- 取込エラー表示
- 取込履歴保存
- 取込後の顧客状態再計算

### 10.4 Phase1では不要なCSV機能

- 外部タグCSV取込
- 回数券CSV専用取込
- 顧客メモCSV高度取込
- AIによる自動名寄せ確定
- 予約システム別プリセット大量対応
- Googleスプレッドシート自動同期

## 11. Phase1 AI実装範囲

### 11.1 初期方針

Phase1では、AI連携を本格化しすぎない。

まずは、以下のどちらかで実装する。

| 方式 | 内容 |
|---|---|
| 診断モック | ルールベースで診断カードを表示 |
| 軽量AI診断 | 店舗KPIサマリのみをAIに渡して診断文を生成 |

### 11.2 Phase1で実装するAI/診断機能

| 機能 | 実装方針 |
|---|---|
| 自社診断 | ルールベース or 軽量AI |
| 今週のアクション | 顧客状態分布から固定ロジックで提案 |
| 顧客状態判定 | AIではなくルールベース優先 |

### 11.3 Phase1では実装しないAI機能

- 顧客別の高度なニーズ推定
- 顧客別LINE文案生成
- セグメント提案AI
- 広告表現チェックAI
- 施策改善AI
- 月次レポートAI
- 代理店提案AI
- エリア需要整理AI

### 11.4 AI入力時の制約

AIを使う場合でも、以下は守る。

- 顧客氏名を渡さない
- 電話番号を渡さない
- メールアドレスを渡さない
- LINE userIdを渡さない
- 顧客メモ全文を渡さない
- 店舗KPIや集計データ中心に渡す

### 14.2 Claude Codeへの依頼粒度

Claude Codeには、1回の依頼で最大1〜2タスクまでにする。

悪い依頼例：

```text

```

良い依頼例：

```text
P1-007 顧客モデル/APIを実装してください。

customersにはstore_idを必ず持たせ、論理削除にしてください。
```

## 17. 実装時の注意点

### 17.1 スコープ膨張を防ぐ

Phase1では、次のような実装を始めない。

- LINE送信ボタン
- Instagram投稿ボタン
- Google投稿ボタン
- Lステップタグ同期
- AIチャット画面の高度化
- 月次レポートPDF
- 代理店プラン

### 17.2 顧客状態判定はまずシンプルにする

最初から複雑なAI判定にしない。

```text
ルールベース判定
↓
画面表示
↓
サンプルデータで確認
↓
後続PhaseでAI補助
```

### 17.3 CSV取込を軽視しない

このサービスの初期価値は、CSV取込の使いやすさに大きく依存する。

最低限、以下は実装する。

- ヘッダー確認
- マッピング
- プレビュー
- エラー表示
- 取込履歴
