# AIコンサルCRM 機能要件定義書 v0.2

## 1. 本書の目的

本書は、AIコンサルCRMに実装する機能要件を定義する。

本サービスは、公式LINEを主要な顧客接点として活用する個人店・小規模店舗向けに、顧客データ・来店/売上データ・LINE友だちデータを統合し、AIが施策提案・配信文生成・対象者抽出・承認・LINE配信実行・結果分析まで支援する、AI搭載型LINE CRMである。

本書では、業務要件定義書 v0.2 で定義した業務フローを、具体的な機能単位に落とし込む。

## 2. 機能設計の基本方針

### 2.1 基本思想

本サービスの中心機能は、単なる顧客管理や配信管理ではなく、以下の一連の流れを支援することである。

```text
データを取り込む
↓
顧客状態・ニーズ・課題を整理する
↓
今やるべき施策を提案する
↓
LINE/SNS/Google/個別対応に落とす
↓
実行状況を管理する
↓
結果を記録する
↓
次回改善案を出す
```

### 2.2 公式LINE・Lステップとの機能上の関係

本サービスは、Phase 1〜4では判断支援・施策設計・代理店管理ツールとして完成し、Phase 5以降でLINE配信実行まで一貫して担うAI搭載型LINE CRMとなる。

Lステップは複雑なシナリオ分岐が必要な場合の任意ツールとして位置づける。本サービスが配信実行の主役となる。

| 領域 | 本サービスの役割 | Lステップの役割（任意） |
|---|---|---|
| 顧客理解 | 顧客状態、ニーズ、阻害要因、次アクションを管理 | 必要に応じてタグ管理 |
| セグメント整理 | 配信対象者リスト、抽出条件、タグ候補を生成 | 実行用タグ、配信対象設定（任意） |
| 配信文作成 | LINE/SNS/Google投稿文を生成 | Lステップ向け文案の流用（任意） |
| LINE配信実行 | **Phase 5〜: 承認済み文案からBroadcast/Multicast/ステップ配信を実行** | 10ステップ超の複雑な自動シナリオ（任意） |
| シナリオ設計 | 初回後、休眠、アップセル等の流れを提案・実行 | 高度なリッチメニュー出し分け（任意） |
| 結果分析 | LINE Insights APIで配信結果を取得し改善提案 | — |

### 2.3 初期実装方針

初期では以下を重視する。

- 公式LINEのみの店舗でも使える
- Lステップなしでも価値が出る
- Lステップ/L Message導入済み店舗にも対応できる
- 自動化よりも診断・提案・実行支援を優先する
- 複雑なタグ設計を本サービス側で吸収する
- 代理店・コンサルが診断/提案/レポートに使える

## 9. F06 セグメント/タグ整理

### 9.1 機能概要

本サービス側で詳細な顧客分類を行い、公式LINEやLステップ/L Message側に渡す実行用の最小タグや対象者リストを作成する。

### 9.2 基本方針

- タグを完全になくすのではなく、外部ツール側のタグを最小化する
- 詳細な顧客理解は本サービス側で持つ
- 外部ツール側には施策実行に必要な情報だけ渡す
- 恒久タグを増やしすぎず、施策単位の一時タグを活用する

### 9.3 主な機能

| 機能 | 内容 | 優先度 |
|---|---|---|
| セグメント候補生成 | 施策目的に応じた対象者条件を生成 | 高 |
| 対象者リスト作成 | 配信・フォロー対象者を一覧化 | 高 |
| タグ候補生成 | 公式LINE/Lステップ用の最小タグ案を生成 | 中 |
| 抽出条件表示 | なぜ対象になったか条件を表示 | 高 |
| 対象者除外 | 配信停止者、同意未取得者を除外 | 中 |
| CSV出力 | 対象者リストをCSV出力 | 高 |
| タグ棚卸し提案 | 不要タグ、重複タグ、使われないタグを提案 | 低/将来 |

### 9.4 外部ツール用タグ例

- 初回後フォロー対象
- 休眠復帰対象
- 休眠予備軍
- アップセル候補
- 回数券更新候補
- VIP候補
- 要個別対応
- 配信停止

## 22. F19 戦略目的整理

### 22.1 機能概要

店舗が今月・今期に優先すべき売上改善目的を整理し、施策提案の前段で「なぜやるか」を明確にする。戦略目的は、KPI、対象顧客、推奨チャネル、推奨施策候補と紐づけて管理する。

### 22.2 主な機能

| 機能 | 内容 | 優先度 | 初期対応 |
|---|---|---|---|
| 重点目的提案 | 売上・来店・顧客状態から今月の重点目的を提案する | 高 | Phase1はルールベースまたは診断モックでカード表示 |
| Why整理 | 目的、背景、根拠、期待効果、注意点を整理する | 高 | Phase1はダッシュボード表示のみ |
| KPI紐づけ | 売上、来店数、再来店率、客単価、休眠復帰数などのKPI候補を紐づける | 中 | Phase2以降 |
| 対象顧客紐づけ | 新規、初回来店後、休眠、VIP候補などの対象顧客セグメントを紐づける | 中 | Phase2以降 |
| 推奨チャネル整理 | LINE、個別連絡、SNS、Google投稿、店頭対応などの推奨チャネルを整理する | 中 | Phase2以降 |
| 推奨施策紐づけ | アクションプラン、施策、文案、対象者リストへ展開する候補を紐づける | 中 | Phase2以降 |
| 人間承認 | 顧客向け発信や外部投稿に展開する前に人間承認を必須にする | 高 | Phase1から方針適用 |

### 22.3 Phase1範囲

Phase1では、ダッシュボードに「今月の重点目的カード」を追加するだけに留める。詳細なKPI目標管理、施策連携、月次レポート反映、外部API連携、自動配信はPhase2以降とする。

### 22.4 制約

- LINE API、Lステップ、L Message、Instagram、Google Business Profile等の外部API連携はPhase1では行わない。
- 戦略目的提案は初期はルールベースまたはAI診断モックでよい。
- AI出力には目的、根拠、信頼度、注意点、不足データを含める。
- 顧客向け発信は必ず人間承認後に実行する。
- 目的・KPI・対象顧客は必ず `tenant_id` / `store_id` の分離を前提に扱う。
