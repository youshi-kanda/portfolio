# AIコンサルCRM AI機能仕様書 v0.2

## 1. 本書の目的

本書は、AIコンサルCRMにおけるAI機能の役割、入力データ、出力内容、判断ルール、制約、承認フローを定義するものである。

本サービスは、公式LINEを主要な顧客接点として活用する個人店・小規模店舗向けに、顧客データ・売上データ・地域ニーズを整理し、集客・再来店・顧客フォロー・発信施策をAIが提案する相談型マーケティングCRMである。

AI機能は、本サービスの中核であり、単なる文案生成ではなく、以下を支援する。

- 自社状況の整理
- 売上課題の診断
- 顧客状態・ニーズの推定
- セグメント・対象者整理
- 公式LINE配信文の生成
- Instagram/Google投稿案の生成
- 今週・今月のアクション提案
- Lステップ導入要否の判断支援
- 施策結果の振り返りと改善提案
- 代理店・コンサル向け診断・提案レポート作成

## 2. AI機能の基本方針

### 2.1 AIの位置づけ

AIは、店舗オーナー、店長、スタッフ、代理店・コンサルを支援する「意思決定補助」「施策設計補助」「発信作成補助」として機能する。

AIは以下を担う。

| 領域 | AIの役割 |
|---|---|
| 分析 | 売上、顧客、発信、施策結果を整理する |
| 相談 | 店舗オーナーや支援者の質問に回答する |
| 提案 | 今やるべき施策や優先順位を提案する |
| 生成 | LINE文、SNS投稿文、Google投稿文、レポート文を作る |
| 整理 | 顧客状態、推定ニーズ、行動阻害要因を整理する |
| 改善 | 施策結果から次回改善案を出す |

AIは以下を担わない。

| 対象外 | 理由 |
|---|---|
| 売上向上の保証 | 外部要因、店舗実行力、顧客反応に左右されるため |
| 法的判断の代替 | 法令・規約判断は専門家確認が必要なため |
| 医療判断の代替 | 整体・鍼灸・美容・健康領域で誤認リスクがあるため |
| 完全自動配信の最終判断 | 誤配信、表現リスク、同意管理リスクがあるため |
| 個人情報の無制限利用 | 最小利用・目的限定が必要なため |

### 2.2 AI出力の基本原則

AI出力には、原則として以下を含める。

| 項目 | 内容 |
|---|---|
| 提案内容 | 何をするか |
| 対象 | 誰に向けた施策か |
| 目的 | 何を改善するための施策か |
| 根拠 | どのデータや状況から判断したか |
| 参照データ | 売上、顧客状態、来店履歴、施策結果など |
| 信頼度 | 高・中・低 |
| 注意点 | 法令、表現、過剰配信、データ不足など |
| 実行手順 | 具体的に何から始めるか |
| 発信用文案 | 必要に応じてすぐ使える文面 |
| 人間確認要否 | 承認が必要かどうか |

### 2.3 人間承認の基本方針

AIは、外部に出る情報や顧客に届く情報について、必ず人間確認を前提にする。

| 出力 | 承認方針 |
|---|---|
| 内部分析コメント | 承認不要 |
| 内部向けアクション提案 | 原則承認不要。ただし実行時に確認 |
| 顧客向けLINE文 | 承認必須 |
| Instagram投稿文 | 承認必須 |
| Googleビジネス投稿文 | 承認必須 |
| キャンペーン告知文 | 承認必須 |
| Lステップ用シナリオ案 | 承認必須 |
| 代理店作成の提案書 | 店舗側承認推奨 |

## 4. AI-01 自社診断AI

### 4.1 機能概要

店舗の売上、顧客、来店、発信、施策状況をもとに、現在の課題と改善優先度を診断する。

### 4.2 主な入力データ

| データ | 内容 |
|---|---|
| 店舗情報 | 業種、エリア、メニュー、強み、課題 |
| 売上データ | 月次売上、客単価、メニュー別売上 |
| 顧客データ | 顧客数、来店回数、最終来店日、累計売上 |
| 予約・来店データ | 予約数、来店数、キャンセル、次回予約有無 |
| 発信データ | LINE配信、Instagram投稿、Google投稿の状況 |
| 施策結果 | 実施施策、反応、予約、売上 |

### 4.3 主な診断項目

- 新規集客不足
- 初回来店後の離脱
- リピート率低下
- 休眠顧客増加
- 客単価低下
- 高単価メニュー未提案
- 発信頻度不足
- LINE運用不足
- SNS/Google投稿不足
- 施策結果の未記録

### 4.4 出力内容

| 出力 | 内容 |
|---|---|
| 現状要約 | 店舗状況を短く要約 |
| 主要課題 | 優先して見るべき課題 |
| 原因仮説 | なぜ課題が起きている可能性があるか |
| 改善優先度 | 高・中・低 |
| 推奨アクション | 次に実行すべき施策 |
| 参照データ | 判断に使った指標 |
| 信頼度 | データ量に応じた信頼度 |
| 不足データ | 追加で必要なデータ |

### 4.5 出力例

```text
今月の主な課題は「初回来店後の2回目予約率の低下」です。

根拠：
- 初回来店者18名のうち、次回予約ありは5名
- 前月より2回目予約率が約12ポイント低下
- 初回来店後フォロー施策が未実施

推奨アクション：
初回来店後3〜5日以内の効果確認メッセージと、次回目的を明確にしたLINE配信を実施してください。

信頼度：中
注意点：初回来店後の満足度データが不足しているため、接客メモやアンケートを追加すると精度が上がります。
```

## 5. AI-02 顧客インサイトAI

### 5.1 機能概要

顧客ごとに、顧客状態、推定ニーズ、行動阻害要因、次アクション、優先度を判定する。

### 5.2 主な入力データ

| データ | 内容 |
|---|---|
| 顧客基本情報 | 氏名、年代、流入経路など |
| 来店履歴 | 初回来店日、最終来店日、来店回数 |
| 売上履歴 | 累計売上、平均単価、メニュー履歴 |
| 予約情報 | 次回予約有無、キャンセル履歴 |
| ニーズ情報 | アンケート、接客メモ、問い合わせ内容 |
| 反応データ | 配信クリック、返信、予約転換 |
| 同意状態 | 配信可否、分析可否 |

### 5.3 判定する項目

| 判定項目 | 例 |
|---|---|
| 顧客状態 | 新規リード、初回来店後、リピーター、休眠予備軍、休眠、VIP候補 |
| 推定ニーズ | 効果確認、価格不安、継続迷い、季節悩み、決め手不足 |
| 行動阻害要因 | 忘れている、予約理由が弱い、価格不安、効果実感不足 |
| 次アクション | LINE配信、個別連絡、相談案内、店頭提案、SNS訴求 |
| 優先度 | 高・中・低 |
| AI信頼度 | 高・中・低 |

### 5.4 顧客状態判定ルール初期案

| 顧客状態 | 条件例 |
|---|---|
| 新規リード | 問い合わせあり、未予約 |
| 初回予約済 | 初回予約あり、未来店 |
| 初回来店後 | 初回来店済、次回予約なし |
| リピーター | 2回以上来店 |
| 休眠予備軍 | 最終来店から45〜60日程度 |
| 休眠顧客 | 最終来店から60日以上 |
| VIP候補 | 来店頻度が高い、累計売上が高い |
| 離脱リスク高 | キャンセル増加、反応低下、来店周期超過 |

※ 日数や閾値は業種別テンプレートで調整可能とする。

### 5.5 出力内容

- 顧客状態
- 推定ニーズ
- 行動阻害要因
- 次アクション
- 優先度
- 判断根拠
- 信頼度
- 注意点
- 推奨メッセージ案

### 5.6 出力例

```text
顧客状態：休眠予備軍
推定ニーズ：再開きっかけ不足、季節悩み
行動阻害要因：予約する理由が弱い可能性
次アクション：季節悩みに合わせたLINE配信
優先度：高
根拠：最終来店から52日経過、過去3回来店、フェイシャル利用履歴あり
信頼度：中
```

## 6. AI-03 セグメント提案AI

### 6.1 機能概要

施策目的に応じて、配信・個別フォロー対象者を抽出し、公式LINEやLステップ/L Messageで使う最小タグ案を生成する。

### 6.2 基本方針

- 複雑な顧客理解は本サービス側で保持する
- 外部ツール側には実行用の最小タグだけを渡す
- 配信停止者・同意未取得者は対象から除外する
- 対象条件と抽出理由を必ず表示する

### 6.3 入力データ

- 施策目的
- 顧客状態
- 推定ニーズ
- 最終来店日
- 来店回数
- 売上/LTV
- メニュー履歴
- 反応履歴
- 配信停止/同意状態
- 外部ツール利用状況

### 6.4 出力内容

| 出力 | 内容 |
|---|---|
| セグメント名 | 例：休眠復帰対象 |
| 対象条件 | 最終来店60日以上、次回予約なし等 |
| 対象人数 | 条件に該当する人数 |
| 除外人数 | 配信停止、同意未取得など |
| 対象者リスト | 顧客一覧 |
| タグ候補 | 外部ツール用の最小タグ名 |
| 配信目的 | なぜこの対象に送るか |
| 注意点 | 過剰配信、表現、値引き等 |
| 推奨文案 | 必要に応じて文案生成へ連携 |

### 6.5 タグ名生成ルール

| タグ種別 | 命名例 | 用途 |
|---|---|---|
| 状態タグ | 初回後フォロー対象 | 継続的な状態管理 |
| 施策タグ | 休眠復帰_2026年05月 | 施策単位の一時利用 |
| 注意タグ | 要個別対応 | 誤配信防止・個別対応 |
| チャネルタグ | LINE配信対象 | 実行チャネル管理 |

### 6.6 出力例

```text
セグメント名：休眠復帰対象
対象条件：最終来店60日以上、次回予約なし、配信同意あり
対象人数：28名
除外人数：3名（配信停止2名、同意未取得1名）
タグ候補：休眠復帰_2026年05月
配信目的：再来店のきっかけ作り
注意点：値引き訴求だけに偏らず、季節悩みや来店理由を明確にする
```

## 7. AI-04 AI相談チャット

### 7.1 機能概要

店舗オーナー、店長、代理店・コンサルが自然文で相談できるチャット機能。

### 7.2 相談カテゴリ

| カテゴリ | 相談例 |
|---|---|
| 売上 | 今月売上が落ちている理由を知りたい |
| 集客 | 新規予約を増やすには何をすべきか |
| 再来店 | 初回来店後のフォローを改善したい |
| 休眠復帰 | 休眠顧客を戻すLINE配信を作りたい |
| アップセル | 高単価メニューを提案する対象を知りたい |
| LINE | 今週送るべき公式LINE配信を考えたい |
| SNS | Instagram投稿を1週間分作りたい |
| Google | Googleビジネスプロフィール投稿案を作りたい |
| Lステップ | Lステップが必要か判断したい |
| レポート | 月次改善レポートを作りたい |

### 7.3 応答フロー

```text
ユーザーが相談入力
↓
相談カテゴリを推定または選択
↓
必要データを特定
↓
データ不足がある場合は補足質問
↓
AIが回答生成
↓
提案内容・根拠・信頼度・注意点を表示
↓
ユーザーが採用/保留/却下を選択
↓
採用した場合は施策・タスク・文案に変換
```

### 7.4 必須出力

- 回答要約
- 提案内容
- 根拠
- 参照データ
- 信頼度
- 注意点
- 次に行う操作

## 8. AI-05 アクションプラン生成AI

### 8.1 機能概要

店舗の状況に応じて、今週・今月やるべきアクションを提案する。

### 8.2 入力データ

- 売上状況
- 予約状況
- 顧客状態分布
- 休眠顧客数
- 発信頻度
- 施策結果
- 店舗課題
- 季節要因
- 業種テンプレート

### 8.3 出力内容

| 出力 | 内容 |
|---|---|
| アクション名 | 例：初回来店後フォロー強化 |
| 目的 | 2回目予約率向上など |
| 対象 | 対象顧客または対象チャネル |
| 優先度 | 高・中・低 |
| 推奨タイミング | 何曜日・何時・今週中など |
| 所要時間目安 | 店舗側の作業負荷 |
| 実行手順 | 具体的な手順 |
| 文案 | 必要に応じてLINE/SNS文 |
| 成果指標 | 予約数、返信数、来店数など |

### 8.4 出力例

```text
今週の優先アクション：初回来店後フォロー
目的：2回目予約率の改善
対象：初回来店後7日以内・次回予約なしの顧客12名
推奨チャネル：公式LINE + 個別フォロー
実行タイミング：来店後3〜5日以内
成果指標：返信数、次回予約数、来店数
```

## 9. AI-06 発信文生成AI

### 9.1 機能概要

公式LINE、Instagram、Googleビジネスプロフィール、メール、店頭POPなどの文案を生成する。

### 9.2 入力データ

- 施策目的
- 対象顧客/セグメント
- 顧客状態
- 推定ニーズ
- メニュー情報
- 店舗の強み
- チャネル
- トーン
- 注意表現
- キャンペーン条件

### 9.3 対応媒体

| 媒体 | 初期対応 | 主な用途 |
|---|---|---|
| 公式LINE | 対応 | 既存顧客・再来店・休眠復帰 |
| Instagram | 対応 | 新規・潜在層への認知獲得 |
| Googleビジネスプロフィール | 対応 | 地域検索・来店前接点 |
| メール | 対応 | 補助チャネル |
| 店頭POP | 対応 | 店舗内訴求 |
| SMS | 将来 | 緊急連絡・リマインド |

### 9.4 出力ルール

| 項目 | 内容 |
|---|---|
| 件名/冒頭 | 媒体に応じた導入文 |
| 本文 | 施策目的に沿った文面 |
| CTA | 予約、返信、相談、確認などの行動導線 |
| 注意文 | 必要に応じて個人差・条件を補足 |
| トーン | 丁寧、親しみ、専門的など |
| 表現チェック | リスク表現を警告 |

### 9.5 禁止・注意表現

以下は警告または修正提案の対象とする。

- 効果を断定する表現
- 医療的効果を保証する表現
- 痩身・美容効果を過度に保証する表現
- 根拠のないNo.1表現
- 過度な不安訴求
- 実態のない期間限定表現
- PR表記が必要な投稿での表記漏れ
- 配信停止者への再配信を促す表現

### 9.6 出力例：公式LINE

```text
こんにちは、〇〇サロンです。
前回のフェイシャル後、お肌の調子はいかがでしょうか？
季節の変わり目は乾燥や毛穴まわりのお悩みが出やすい時期です。

前回のケアから少し期間が空いているため、今の状態に合わせたメンテナンスのご相談も可能です。
ご希望の方は、このメッセージに「相談」と返信してください。
```

## 10. AI-07 施策改善AI

### 10.1 機能概要

実施した施策の結果を分析し、良かった点、課題、次回改善案を提示する。

### 10.2 入力データ

- 施策内容
- 対象者数
- 配信文/投稿文
- 配信日/投稿日
- 返信数
- クリック数
- 予約数
- 来店数
- 売上
- 店舗所感
- 過去施策結果

### 10.3 出力内容

| 出力 | 内容 |
|---|---|
| 結果要約 | 実施結果の概要 |
| 良かった点 | 反応が良かった要因 |
| 課題 | 予約転換や反応不足の原因仮説 |
| 改善案 | 次回変えるべき点 |
| 次回対象者 | 対象条件の見直し案 |
| 次回文案 | 改善後の文案案 |
| 信頼度 | データ量に基づく信頼度 |

### 10.4 出力例

```text
今回の休眠復帰配信は、返信率は高い一方で予約転換が低い結果でした。

原因仮説：
- 空き枠や所要時間が明記されていない
- 予約リンクまたは返信導線が弱い
- 値引きよりも来店理由の提示が不足している

次回改善案：
- 空き枠候補を2〜3つ明記する
- 所要時間を入れる
- 季節悩みに合わせた来店理由を冒頭に入れる
```

## 11. AI-08 Lステップ要否診断AI

### 11.1 機能概要

店舗が公式LINEだけで運用すべきか、Lステップ/L Message等の高度ツールを導入すべきかを判断支援する。

### 11.2 入力データ

| データ | 内容 |
|---|---|
| 顧客数 | LINE友だち数、既存顧客数 |
| 配信頻度 | 月間配信回数 |
| セグメント数 | 必要な対象分類の数 |
| シナリオ数 | 初回後、休眠、アップセルなどの自動化要否 |
| 運用体制 | オーナーのみ、スタッフあり、代理店支援あり |
| 予算感 | 月額費用・構築費を許容できるか |
| 現在の課題 | 手動運用で困っている点 |
| 施策数 | 毎月実行したい施策数 |

### 11.3 判断軸

| 判断軸 | 公式LINEのみで足りる可能性が高い | Lステップ等が必要な可能性が高い |
|---|---|---|
| 顧客数 | 少ない | 多い |
| 配信対象 | 大まかでよい | 細かく分けたい |
| 自動化 | 手動で対応可能 | ステップ配信が必要 |
| 運用体制 | オーナー中心 | 支援者/スタッフあり |
| シナリオ | 単発配信中心 | 初回後・休眠・アップセルを自動化したい |
| 予算 | 低く抑えたい | 構築費・月額費用を許容できる |

### 11.4 出力内容

- 診断結果
- 推奨構成
- 理由
- 公式LINEのみで行う場合の運用案
- Lステップ等を導入する場合の設計案
- 最小タグ案
- 注意点

### 11.5 出力例

```text
診断結果：現時点では公式LINE + 本サービスで運用可能です。

理由：
- 配信対象の分類が3〜4種類程度で足りる
- 毎月の施策数が少なく、手動運用でも対応可能
- 複雑なステップ配信の必要性がまだ低い

推奨：
まずは本サービスで対象者リストとLINE文を作成し、公式LINEで手動運用してください。
顧客数や施策数が増えた段階で、Lステップ導入を再検討してください。
```

## 16. AI-13 戦略目的整理AI

### 16.1 機能概要

店舗の売上、来店、顧客状態、施策履歴、店舗課題をもとに、今月・今期に優先すべき売上改善目的を整理する。施策案を出す前に Why を明確化し、目的、KPI候補、対象顧客、推奨チャネル、推奨施策候補をつなげて提示する。

### 16.2 主な入力データ

| データ | 内容 |
|---|---|
| 店舗情報 | 業種、エリア、強み、課題、重点メニュー |
| 売上データ | 月次売上、客単価、メニュー別売上、前年・前月比較 |
| 予約・来店データ | 来店数、初回来店、再来店、キャンセル、次回予約 |
| 顧客インサイト | 顧客状態分布、休眠候補、VIP候補、推定ニーズ |
| 施策履歴 | 実施施策、反応、予約、売上、未実施アクション |
| 診断結果 | 自社診断AIまたはルールベース診断の課題・根拠 |

### 16.3 出力内容

| 出力 | 内容 |
|---|---|
| 目的 | 今月・今期に優先すべき戦略目的 |
| 根拠 | 売上・来店・顧客状態・施策履歴からの判断理由 |
| 信頼度 | high / medium / low |
| 注意点 | 過剰配信、データ不足、季節要因、広告表現リスクなど |
| 不足データ | 判断精度向上に必要な未入力データ |
| KPI候補 | 売上、来店数、再来店率、客単価、休眠復帰数など |
| 対象顧客 | 新規、初回来店後、休眠、VIP候補など |

### 16.4 初期実装方針

Phase1ではルールベースまたは診断モックで生成し、ダッシュボードの「今月の重点目的カード」に表示する。詳細なKPI目標管理、施策連携、月次レポート反映、自動配信、外部API連携はPhase2以降とする。顧客向け発信に展開する場合は必ず人間承認を必須にする。

## 17. AI共通制御仕様

### 17.1 参照データ制御

AIは相談内容や機能に応じて、必要なデータのみを参照する。

| 相談内容 | 主に参照するデータ |
|---|---|
| 売上相談 | 売上、来店、客単価、施策履歴 |
| 休眠客対策 | 最終来店日、来店回数、配信履歴、ニーズ |
| LINE配信相談 | 顧客状態、配信履歴、同意状態、反応 |
| Lステップ判断 | 顧客数、配信頻度、シナリオ要否、運用体制 |
| SNS相談 | メニュー、強み、エリア、発信履歴 |
| レポート作成 | 店舗情報、売上、顧客状態、施策結果 |

### 17.2 信頼度表示ルール

| 信頼度 | 条件 |
|---|---|
| 高 | 必要データが十分あり、過去施策結果もある |
| 中 | 基本データはあるが、反応データやニーズ情報が不足 |
| 低 | データが少なく、一般的な業種テンプレートに依存 |

### 17.3 データ不足時の応答

データ不足時は、断定せず、以下を表示する。

- 不足しているデータ
- 現時点で言えること
- 追加すると精度が上がるデータ
- 一般的な業種テンプレートに基づく仮提案

### 17.4 禁止応答

AIは以下の応答をしてはならない。

- 売上向上を保証する
- 医療効果・美容効果を断定する
- 法的に問題ないと断定する
- 配信停止者への配信を促す
- 顧客個人情報を不要に露出する
- 外部ツールの仕様を未確認のまま断定する
- Lステップ不要/必須を無条件に断定する
